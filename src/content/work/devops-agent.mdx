## 1. Context

Engineers spend a share of every week on routine checks: is the server healthy, what is in the logs, has anything new appeared in a security scan, are the containers behaving. This agent is being built to take that share.

## 2. Problem

The checks are repetitive and easy to postpone, which is exactly how small problems become incidents. The goal is an agent that does the checking and the first pass of diagnosis, without ever applying a change on its own.

## 3. Decisions

- **Diagnose, propose, wait.** The agent reads, analyses and suggests. It does not act.
- **Approval before remediation.** An engineer approves each fix before it is applied.
- **Cover the environments actually in use:** VPS hosts, Docker and Kubernetes.

## 4. Architecture

Servers, containers, logs and scan output feed the agent. It produces findings and proposed remediation. An engineer reviews and approves; only then is the fix applied.

## 5. Where humans stay in the loop

Suggested remediation is applied only after human approval. For infrastructure this is not optional: a wrong fix applied automatically is worse than no fix.

## 6. Capability areas

- Server health monitoring and log analysis.
- Security scanning and vulnerability detection.
- Docker and Kubernetes checks.
- Suggested remediation, applied only after human approval.
